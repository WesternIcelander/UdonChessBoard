# Settings: `ChessArbiter`

An arbiter is the official who enforces the rules at a chess event, which matches what this object does.

- Holds the rules settings: whether takebacks are allowed, each draw rule (agreement, threefold, fifty-move, fivefold, seventy-five-move, dead position; "No draws" is all draw rules off), the inactivity times, and the forced lobby settings (an optional forced mode and an optional forced time control; see [Starting](board-lifecycle.md#starting)).
- Defaults come from the world's configuration in the editor. Only organizers can change settings in-world.

## Instance defaults

`ChessArbiter` in `Assets/Siggi/ChessBoard/ChessArbiter.cs`.

- **Setting bits** (`Setting*` constants, `SettingCount` = 10, the lowest bits): `SettingTakebacks`, the six draw rules (`SettingDrawAgreement`, `SettingThreefoldRepetition`, `SettingFiftyMoveRule`, `SettingFivefoldRepetition`, `SettingSeventyFiveMoveRule`, `SettingDeadPosition`; together `SettingsDrawRules`), `SettingModeForced`, `SettingClockForced`, `SettingPlayOnAfterFlagFall` (step 12.9: a game whose flag falls plays on untimed, see [Clocks](clocks.md)).
- **Numeric settings** are an `int[NumberCount]` (5) indexed by `NumberResetAvailableTime`, `NumberAutoResetTime` (seconds, `Never` = -1), `NumberForcedMode` (`ChessGame.Mode*`), `NumberForcedBaseTime` (seconds, `NoClock` = -1) and `NumberForcedIncrement` (seconds).
- **Editor values:** one Inspector field per setting (`takebacksAllowed`, `drawAgreement`, ..., `resetAvailableTime`, `autoResetTime`, `modeForced`, `forcedMode`, `clockForced`, `forcedBaseTime`, `forcedIncrement`, `playOnAfterFlagFall`). Starting values: takebacks on, every draw rule off ("No draws"), playing on after a flag fall on, reset-available 120 s, auto-reset 600 s, nothing forced (forced values Standard, 600+0).
- On `Start`, every client copies the editor values into the synced `defaultSettings` (`int`) and `defaultNumbers` (`int[5]`), unless a serialization has already arrived (a late joiner whose `OnDeserialization` ran first keeps what was synced). All clients start from the same editor values, so nobody needs to serialize until settings change.
- **Invalid editor numbers are corrected** (`FixNumbers`), with a warning naming the object: a time below -1 becomes -1, a reset-available time above the auto-reset time (both set) becomes the auto-reset time ([Inactivity](inactivity.md)), an unknown forced mode becomes Standard, a negative increment becomes 0.
- Read with `IsDefaultOn(setting)` and `DefaultNumber(number)`; `SettingsToString` and `NumbersToString` give them as text for logs. Changed in-world with `SetDefaultSetting(settings, on)` (one or several bits) and `SetDefaultNumber(number, value)`, which corrects the numbers with `FixNumbers` (so an auto-reset time set below the reset-available time clamps the latter), as part of an organizer's change (below).
- **Default piece sets** (steps 12.3 and 12.10): `defaultWhitePieceSet` and `defaultBlackPieceSet`, the `ChessPieceSet`s White and Black wear on every board view without a set of its own for that side ([Physical pieces](physical-pieces.md#piece-sets-steps-123-and-1210), [Customizing](customizing.md#chess-piece-sets-steps-123-and-1210)). Not settings: not synced, and changed only locally with `SetDefaultChessPieces(color, set)`, which refuses `null` (returns `false`); `DefaultPieceSet(color)` reads them. The arbiter only holds the references, and tells the board views that registered with it (`AddPieceSetListener`, `pieceSetListeners`) when one changes (`OnDefaultPieceSetChanged(color)`). Either field empty cancels a build ([Organizers](organizers.md), the build check).

## Changing settings in-world

- **Synced, manual sync**: `defaultSettings`, `defaultNumbers` (the inactivity times are numbers 0 and 1), `overrideMask`, `overrideSettings` and `overrideNumbers`. Every client reads the settings from its own copy; whoever owns the arbiter sends them.
- **Only organizers may own the arbiter** (see [Organizers](organizers.md)): `OnOwnershipRequest` allows a transfer only to a player `IsOrganizer` accepts (`MayOwn(who)`), checked on the requesting client and on the owner.
- **An organizer's change** (the settings menu, step 11; for now the debug view's arbiter buttons): `BeginChange()` returns `false` unless the local player is an organizer, otherwise makes them the owner (`Networking.SetOwner`) and returns whether they own it; then the setters; then `EndChange()`, which serializes (`RequestSerialization`; `false` if not the owner). Late joiners get the last settings sent.
- The plain setters stay local so that tests can change and restore settings without sending anything.
- Boards don't watch the arbiter: they read the settings when they take a snapshot, so a change reaches a board in use only through a re-snapshot.

## Per-board overrides

- Each setting has an instance-wide default, and any board can override any setting, e.g. a tournament board with no takebacks next to casual boards.
- **Encoding:** each setting is one bit, so a full set of settings is one `int`. The arbiter holds:
  - the instance defaults (`int`),
  - per board: an override mask and override values (`int[]` each, indexed by board number).
  - A board's effective settings are `(defaults & ~mask) | (values & mask)`: overridden bits come from the board, the rest from the defaults.
  - On/off settings include "mode forced" and "clock forced".
  - **Numeric settings** aren't on/off, so they're stored as separate values: instance defaults plus per-board `int[]` overrides, with a bit in the override mask saying whether the board overrides each one. There are five:
    - reset-available time and auto-reset time (seconds, `-1` = never; see [Inactivity](inactivity.md)),
    - forced mode (used only while "mode forced" is on),
    - forced base time and forced increment (seconds, base `-1` = no clock; used only while "clock forced" is on).
- **Implementation** (`ChessArbiter`):
  - `boardCount` (Inspector, starting value 4) sets how many boards can have overrides, numbered 0 to `boardCount` − 1. On `Start` the synced arrays `overrideMask`, `overrideSettings` (`int[boardCount]` each) and `overrideNumbers` (`int[boardCount × NumberCount]`, flat since synced arrays can't nest) are created empty, unless a serialization has already arrived; `BoardCount()` is their synced length. A board number outside the range (`HasBoard`) has no overrides and always gets the defaults.
  - Mask bits: the setting bits themselves (`OverrideSettingsMask`), then `OverrideNumberBit(number)` = `1 << (SettingCount + number)` per numeric setting (`OverrideNumbersMask`).
  - `CombineSettings(defaults, mask, values)` is the formula above; `EffectiveSettings(board)` / `IsEffectiveOn(board, setting)` apply it. `EffectiveNumbers(board, numbers)` / `EffectiveNumber(board, number)` take each overridden number from the board and the rest from the defaults, then **correct the result with `FixNumbers`**, since an override can conflict with a default (an auto-reset time overridden below the default reset-available time clamps the latter). Override values are kept as given.
  - Setters for the settings menu: `SetSettingOverride(board, settings, on)` (one or several bits), `ClearSettingOverride`, `SetNumberOverride(board, number, value)`, `ClearNumberOverride`, `ClearOverrides(board)`; they return `false` for a board out of range. Readers: `IsSettingOverridden`, `SettingOverrideValue`, `IsNumberOverridden`, `NumberOverrideValue`. The setters only change the local copy; an organizer's change wraps them as below.
- **Stored on the arbiter, not the board.** Overrides must survive a board reset, which clears all of the board's state, and changing them only needs ownership of the arbiter. Boards are given their board number in the editor.
- The settings menu (a view of the arbiter) lets an organizer pick "all boards" or a specific board, and set each setting to on, off, or "use default" for a board.
- **Snapshot:** a board copies its effective settings (the bits and all five numeric settings) into its own synced state when it leaves the reset state (someone joins a seat, or a game is loaded or imported), and uses that copy until it's reset. Changing settings doesn't alter the rules of a board already in use.
- **Re-snapshot on request:** if a mistake was made, an organizer can tell a board, or all boards, to take a new snapshot. The organizer takes ownership of the board (see [Ownership](ownership.md)), the board re-copies its effective settings, and serializes.
- **Implementation** (`ChessBoard`): the board's Inspector fields `arbiter` (the world's `ChessArbiter`) and `boardNumber` (its number for per-board overrides; a number the arbiter has no overrides for gets the defaults). The snapshot is `gameSettings` (bits) and `gameNumbers` (`int[5]`, the corrected effective numbers), both empty (0) on a reset board; read them with `IsGameSettingOn(setting)` and `GameNumber(number)`.
  - `TakeSnapshot()` copies `EffectiveSettings(boardNumber)` and `EffectiveNumbers(boardNumber, ...)`. `JoinAs` calls it when the first join takes the board from reset to the lobby (later joins don't); loading a game calls it too (step 7.9a). It then applies the forced lobby settings so the lobby shows them: the forced mode and clock in the lobby, only the forced clock on a loaded board (its mode is the loaded game's); a game already started keeps its mode and clock. Start applies them again, so the game always has the forced values. With the `arbiter` field empty (the board logs an error on `Start`), the snapshot is every bit off, both inactivity times `Never`, Standard, no clock.
  - `Resnapshot()` / `ResnapshotAs(who)` (a `VRCPlayerApi`): accepted when `arbiter.IsOrganizer(who)` and the board isn't reset (a reset board has no snapshot; it takes one on leaving the reset state); it calls `TakeSnapshot()`, so new forcing applies to the lobby and lifted forcing leaves the shown values as the players' choices. Like every change, it takes ownership of the board and is sent (8.3). The settings menu's "all boards" calls it on each board.

## Settings menu (step 11.1a)

`ChessSettingsMenu` (`Assets/Siggi/ChessBoard/ChessSettingsMenu.cs`), a view of the arbiter: it holds no settings and no synced fields, and changes them only through the arbiter's `BeginChange`, setters and `EndChange`.

- **Who sees it:** the controls (`controls`, a child object) are shown only while the local player `IsOrganizer`, checked once a second (`UpdateVisibility`), since `FirstJoinerAuth`'s name arrives by sync and the master can change. Everyone else sees the title and a notice ("Only organizers can change these settings."). A press refused by `BeginChange` (rights lost within the second) hides the controls at once.
- **Scope:** the top row picks what the menu shows, local to the player (`scope`): **All boards** (the instance defaults) or **Board N** (board number N − 1, one for each board the arbiter has overrides for, `BoardCount()`), stepped with **<** and **>** (wrapping). For a board, **All default** clears every override it has (`ClearOverrides`).
- **Rows** (`Item*`), each with its label, its value and three buttons:
  - On/off settings: Takebacks, **All draw rules** (every draw rule at once; Off is labelled **No draws**), then each draw rule, **Force the mode**, **Force the time control**, and (after the forced values) **Play on untimed after a flag fall** (12.9). Buttons **On**, **Off** and, for a board, **Default** (the board uses the instance default again).
  - Numbers: **Forced mode** (Standard, Chess960), **Forced base time** (`baseTimes`: no clock, 1, 3, 5, 10, 15, 30, 60, 90 min), **Forced increment** (`increments`: 0, 1, 2, 3, 5, 10, 15, 30 s), **Anyone can reset after idle** and **Board resets itself after idle** (`inactivityTimes`: 30 s, 1, 2, 5, 10, 15, 30, 60 min, then **Never**). Buttons **<** and **>** step through the list (a value not in it, e.g. from the editor, steps to the nearest choice that way; nothing past either end), and for a board **Default**. The forced values are shown and set whether or not their forcing is on.
- **Values:** all boards show the defaults; a board shows its effective value (numbers corrected by `FixNumbers`, so an auto-reset time below the reset-available time shows the latter clamped), with ` (default)` when the board doesn't override it. A group of bits set differently (some draw rules on, some off) shows **Mixed**. The current choice is tinted (`selectedButtonColor`): On or Off when every bit of the row is that way (for a board, overridden that way), Default when the board overrides none of the row; numbers mark only Default. Default buttons are hidden for all boards.
- **Clamping:** for all boards, `SetDefaultNumber` corrects the defaults at once, so lowering the auto-reset time below the reset-available time lowers the latter too, and raising it again doesn't put it back. A board's overrides are kept as set and corrected only in the effective value.
- **Redrawing:** the arbiter counts every change (`changes`: each setter, and each serialization arriving in `OnDeserialization`); the menu redraws when it moves on (`RefreshIfChanged`), so a change made by another organizer shows at once.
- **Pressing:** each button has a `ChessSettingsButton` (`menu`, `item`, `action`; its UI Button calls `Press`), which calls `ChessSettingsMenu.Press(item, action)`. A press that wouldn't change anything (the current choice, a step past the end, Default with nothing overridden) does nothing and sends nothing. Every change is logged: `[ChessSettingsMenu] <player>: <scope>, <row>: <button>` (with the new value for numbers).
- **Changes don't reach a board in use** until it re-snapshots or takes its next snapshot; see Snapshot above.
- **Re-snapshot (step 11.1b):** below the settings, **Apply to boards in use: Apply now** (`ItemResnapshot`, `ResnapshotBoards`) makes the boards shown take a new snapshot: every board on the arbiter for All boards, otherwise the boards with that board number (`boards`, every `ChessBoard` on the arbiter, set by the builder). Each board in use goes through `ResnapshotAs` (organizers only; it takes ownership of the board and sends it). A reset board has no snapshot and takes the settings when it's next used, so it's only counted. The outcome shows on the line below (`resnapshotLabel`, `ResnapshotText`: "2 boards updated, 1 not in use", "No board in use: each takes the settings when next used", "No such board") and is logged as `[ChessSettingsMenu] <player>: <scope>, re-snapshot: <outcome>`; it's cleared when the scope or a setting changes. Settings changes and re-snapshots stay separate presses, so an organizer can change several settings before applying them.
- **Empty Simple Auth field (step 11.1b):** while the arbiter's `simpleAuthMissing` is set, nobody is an organizer, so the controls are hidden from everyone and the notice says why (`SimpleAuthMissingText()`, from the language pack like every text of the menu, step 13.5: the title, row and button labels too, which the builder leaves empty): "Settings can't be changed: the Chess Arbiter's Simple Auth field is empty, so nobody is an organizer. Set it in the editor (NoOneAuth if nobody should change settings)."
- **Built** by **Tools > Chess Board > Create Settings Menu** (`Editor/ChessSettingsMenuBuilder.cs`) for the scene's only arbiter: a world-space canvas 2.5 m to the right of the boards (along +x), facing them. An existing menu is replaced in place, and whatever pointed at it is pointed at the new one; an empty `ChessSettingsMenu` field (`SettingsTest`'s `menu`) gets it.
