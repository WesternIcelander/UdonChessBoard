# Clocks

- **Time control:** base time plus an increment per move (e.g. 5+3), or no clock. Shown in the lobby; recorded in the PGN as the standard `[TimeControl "300+3"]` tag (seconds), or `"-"` for no clock (`"?"` when unknown, e.g. a game imported without the tag).
- **Who chooses:** the players, in the lobby, unless organizers have forced a time control in the settings UI. Forcing is a setting like any other: a "clock forced" bit plus the forced base and increment, as instance defaults with per-board overrides, included in the snapshot. On a loaded game, the clock is chosen the same way, and continuing starts both sides with fresh clocks (see [Continuing a loaded game](replay.md#continuing-a-loaded-game)).
- **Synced state:** each side's remaining time (milliseconds, `int`) and the server time when the current turn began (`double`, `Networking.GetServerTimeInSeconds()`). Every client computes the running clock from those, so nothing needs syncing while a player thinks.
- **On each move:** the mover's remaining time is reduced by the time since their turn began, the increment is added, and the turn start resets. This is part of the same serialization as the move.
- **Per-move clock history:** the remaining time after each move is stored alongside the move history (`int[]`). This lets a takeback restore the clocks at that point, and lets the PGN include standard `[%clk 0:04:58]` comments.
  - Export writes `H:MM:SS`, adding tenths (`0:09:57.6`) when they aren't zero, so an imported VRChess or Lichess clock comes back out with the same value.
  - PGN import fills the history from the PGN's `[%clk]` comments, with `-1` for moves that have none (see [PGN import](pgn.md#import-local-rare)), so a loaded game keeps its clocks for replay and re-export. A game loaded from the archive has its stored history.
- **Flag fall:** when a side's time reaches zero, every client can see it. The board's current owner ends the game (once, as with the automatic reset). FIDE rules: the side out of time loses, unless the opponent has no way to checkmate, in which case it's a draw. That exception is a draw rule, so under "No draws" a timeout is always a loss.
- **Playing on untimed after a flag fall** (step 12.9): unless organizers have turned it off (the setting `SettingPlayOnAfterFlagFall`, on by default, see [Settings](settings.md)), the game that ended on time (logged as usual) continues at once as an untimed continuation game: a new Game ID with `ContinuedFrom` (the ended game's ID and its last ply), no clock, the same players and position. The board still gives each side's time at the end of the timed game (the flagged side's 0) and says the clocks are from the previous game, so the UI shows `GG` in place of `0:00` for the side out of time.
- **A player leaving doesn't stop their clock**: their time runs out as normal.
- **The clock doesn't pause in replay.** Replay pauses moves, not time: the player to move keeps using their time while the board is in replay.
- Time forfeit is a new row in Game endings.

## Implementation

On `ChessBoard` (`Assets/Siggi/ChessBoard/ChessBoard.cs`). The time control is `baseTime` and `increment` (seconds, base `ChessArbiter.NoClock` for none), the clocks `whiteTime`/`blackTime` (ms, each side's time when its turn began) and `turnStart` (server time). Each method that needs the time has an `*At(..., now)` form taking the server time, which tests use; the plain form uses `ServerTime()` (`Networking.GetServerTimeInSeconds()`).

- **Running:** `IsClockRunning()` is a game in progress (`LifecycleInGame`, replay included) with a clock. Only the side to move's clock runs. `RemainingTimeAt(color, now)` is that side's stored time less the whole milliseconds since `turnStart` (rounded down; a time before the turn start counts as none passed), never below 0; the other side's, and both when the clock isn't running (lobby, loaded, ended, no clock), are as stored (0 with no clock).
- **Flag fall:** `FlaggedColorAt(now)` is the side to move when its remaining time is 0, `ChessRules.NoColor` otherwise. A move is refused once the flag has fallen, so the side not to move always has time left. `CheckFlagFallAt(now)` ends the game on it (time forfeit; see [Game endings](game-endings.md#implementation)); the board calls `CheckFlagFall()` from `Update` while a game is in progress, which only the owner does (8.3).
- **Playing on** (12.9): `CheckFlagFallAt` ends the game on time (logged), then, while the snapshot has `ChessArbiter.SettingPlayOnAfterFlagFall` on and no automatic draw the snapshot has on applies to the position, `PlayOnUntimedAt(now)` continues it, in the same change (told as `ChangeEnded`): `ContinueGameIdAt(moveCount, …)`, the clock history emptied (`-1`), `baseTime` `NoClock` and increment 0, `turnStart` now, back in game with no result, a pending takeback request cleared, replay left as it is. `whiteTime`/`blackTime` keep the timed game's end (the flagged side's 0); `untimedAfterFlagFall` (synced) says so (`ClocksFromPreviousGame()`), and `flagFallPly` (synced) is the ply the flag fell at while the game is that flag fall's own continuation (−1 otherwise).
  - **Decided in 12.9:** a drawn time forfeit (the opponent can't mate) plays on too, since the side out of time may still mate; but not when an automatic draw applies (a dead position with that rule on), as the untimed game would be over before a move. A takeback in the untimed game, even to before the flag fell, stays untimed and keeps the times (`RestoreClocks` leaves them; the new game has `flagFallPly` −1). The untimed game's PGN has `TimeControl "-"` and no `[%clk]` (the timed moves' clocks are emptied: they're in the timed game's PGN, and a `[%clk]` under `"-"` would contradict it).
  - **Logging:** a game played on with no move since the flag fell (`moveCount == flagFallPly`) isn't logged, however it ends (a reset, a resignation, a takeback); after a move it's logged like any continued game.
- **Stopping:** when a game ends, the side to move's clock is stopped with the time it had left stored in `whiteTime`/`blackTime` (0 on a time forfeit), so an ended game keeps showing it.
- **Moves:** `PlayMoveAt(move, now)` plays a legal move as the game's next move: refused unless in game and not in replay, once the mover's flag has fallen, and for a move not in the position's legal list. It records the move, its SAN (`ChessNotation.MoveToSan`), the halfmove clock before it, and the move number; with a clock, the mover's time becomes their remaining time plus the increment (capped at `int.MaxValue`), which also goes into `clockHistory` (`-1` with no clock); `turnStart` becomes `now`. Who may move and matching a drop to a move are the input API (7.4a), which calls `PlayMove`. A move that checkmates or stalemates ends the game (see [Game endings](game-endings.md#implementation)).
- **Takeback:** `AcceptTakebackAs` (see [Replay](replay.md#implementation)) restores each side's time from the clock history entry of its last move before the ply, or the base time when it hadn't moved, and starts the turn then.
- **Continuing a loaded game:** `ContinueGameAs` (see [Replay](replay.md#implementation)) gives both sides the base time and empties the clock history before the continuation point, so a takeback to a ply before it restores the base time.
- **History room:** the history arrays start with `InitialHistoryCapacity` (128) entries and double together when full; new notation entries are `""` and new clock entries `-1`.
